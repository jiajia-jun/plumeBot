# 功能指南

面向使用者与二次开发者的功能设计说明。本文只讲「是什么 / 怎么用 / 边界在哪」，内部实现细节以 [架构设计](../architecture.md) 为唯一准绳。

## 1. 消息管线

每条消息进入后先走一条固定管线，再决定是否回复：

```
NapCat → OneBot WS
  ├── [1] 日志        —— 所有消息先落日志（含后续被拦截的）
  ├── [2] 限流        —— 令牌桶：短时间大量消息降级（超时回固定文案并丢弃）
  ├── [3] 敏感词过滤  —— Aho-Corasick 自动机；命中回「我拒绝回答」并丢弃
  ├── [4] 持久化      —— 写入内存上下文窗口 + SQLite messages 表
  │
  ├── 是命令（/ 开头）？ → 插件分发 → 回复
  └── 是普通消息？     → 触发判断（见 §3）→ 命中则走回复闭环
```

即使消息被规则拦截（限流 / 敏感词 / 触发判断不命中），它也已经**旁听进来**（进了窗口和存储）——被 @ 时上下文永远完整。

## 2. 记忆系统

### 2.1 三级记忆

| 层级 | 载体 | 内容 | 生命周期 |
|------|------|------|---------|
| 短期 | 内存 ring buffer 上下文窗口 | 最近 20 → 100 轮对话 | 进程期间，重启失（SQLite 已存全量消息） |
| 中期 | LLM 压缩摘要 | 窗口满后旧消息压成摘要，多摘要再融合、FIFO 淘汰；热链在内存、归档落 SQLite，重启自动回灌 | 随窗口滚动持续更新 |
| 长期 | SQLite `member_facts` / `group_jargon` | 成员事实与群黑话（**Agent 在对话中经 tool 自主读写**） | 持久 |

- **成员事实**：`(group_id, user_id, fact)` 原子条目，一条一记独立去重/删除；`group_id` 空 = 私聊记忆，非空 = 群聊记忆（同人在不同群记不同事实）；
- **群黑话**：`group_jargon` 带 **pending → confirmed** 审核状态机，只有 confirmed 才注入 prompt；管理控制台可审核（见 [管理后端指南](admin.md)）；
- **会话键约定**：群聊 = `GroupID`，私聊 = `private:`+UserID，贯穿窗口、摘要归档、运行态与触发控制状态。

### 2.2 Prompt 五段组装

每次触发回复时实时组装五段 prompt：

```
① 系统人格     —— persona 表模板的 system_prompt（定义「你是谁」）
② 会话画像     —— 群画像（文化/话题/黑话）+ 窗口内成员事实（每成员各 N 条）
③ 压缩摘要     —— 历史上下文（全量拼接）
④ 当前窗口     —— 最近 N 轮原始消息
⑤ 当前消息     —— 正在处理的这条
```

画像（聚合标签）有界、整行重写；事实/黑话（原子条目）无界、逐条累积；**读在组装、写在 tool**——prompt 组装时现查注入，Agent 执行中经 tool 写入。注入量有上限（`llm.prompt.*`），不无界灌入 token。

## 3. 触发控制

### 3.1 触发模式

| 模式 | 行为 |
|------|------|
| `mention` | 仅被 @ 或私聊时回复；所有消息仍旁听进窗口 |
| `auto` | @ 和私聊一定回复；普通消息由 Agent 自主判断是否加入 |

触发模式只控制「**是否回复**」，不影响「是否收消息」。

每个群可独立配置（`group_config` 表）。群首次被 bot 触达时按当时的全局生效值**自动建行**，此后该群配置**独立于全局**（详见 [管理后端指南](admin.md) §5）。

### 3.2 状态规则（纯规则层，不调 LLM）

auto 模式下，普通消息是否由 Agent 判断，先过五条规则：

| 规则 | 阈值默认值 | 说明 |
|------|-----------|------|
| 精力值 | 上限 100，回复消耗 10，恢复 5/分钟，低于 20 不主动说话 | 有「电量感」，别吵 |
| 冷却间隔 | 60 秒 | 两次主动回复最小间隔 |
| 连续回复上限 | 5 次，超限强制休息 300 秒 | 防空转刷屏 |
| 时段控制 | 静默 23:00–07:00（支持跨午夜） | 深夜/凌晨不主动参与；@ 仍回复 |
| 短消息忽略 | <4 字 | 短消息不触发 Agent 判断 |

**规则边界**：只约束「主动发言」（auto 模式下的普通消息）；被 @ / 私聊 = 强制回复，绕过全部状态规则（mention 模式规则不生效）。**拦截 ≠ 丢弃**：被拦消息只是不回复，仍旁听缓存。

按群可通过管理控制台覆盖每项参数（`group_config` 列值非 0/非空即覆盖全局默认）。

## 4. 人格

人格不是配置文件里的一行 system prompt，而是 SQLite `persona` 表中的**模板**（按 agent 名绑定）：

- **改表即时生效**：BuildMessages 每轮组装现查模板，改 `system_prompt` 下一条消息即生效，无需重启；
- **兜底链**：`persona` 模板 `system_prompt` → `config.agent.system_prompt` → 内置默认人设；
- **维护**：推荐在管理控制台的「人格」页维护（put 即生效），也可以直接改库。

## 5. 多模态感知

图片**惰性描述**接入对话：

- 只有**最近 N 轮 + 当前消息**的图片会被描述（`llm.prompt.describe_recent_rounds`），控制预算；
- 描述结果缓存在内存（同图不重复调模型），并写回存储复用；
- 需要启用一个视觉模型条目并设 `llm.vision_model`（见 [配置参考](configuration.md)）；未启用时图片在 prompt 中降级为 `[图片]`。

## 6. AI 群管理

Agent 可以自主调用 4 个工具管理群：`group_mute` / `group_unmute` / `group_kick` / `group_set_card`。所有动作都收敛到**唯一执行入口**，三道护栏：

1. **群总开关**：`group_config.group_mgmt_enabled`（自动建行默认写 1 = 开，显式设 0 关闭）；
2. **管理员校验**（fail-closed）：触发者与 bot 都必须是群主/管理员——实时查群成员角色，查询失败 / 无 role 一律拒绝；
3. **时长钳制**：禁言时长上限 30 天。

动作结果逐条反馈（`APIResponse` 检查），失败不静默。这是高危能力，护栏与门槛只紧不松。插件 `Actions` 与 AI 工具走**同一套护栏链**。

## 7. 记忆工具

Agent 在对话中自行判断何时调用（不提供查询型 tool——数据小，直接注入更稳）：

- `store_fact`：记一条成员事实（写 `member_facts`）；
- `learn_jargon`：学一条群黑话（进 pending，待审核）；
- `forget_fact`：删一条已记事实。

启用/禁用见 `tools.enabled`（[配置参考](configuration.md)）。

## 8. 日志与运维

### 8.1 日志文件

日志只写文件不写终端，按**精确级别分文件**：

| 文件 | 记录 |
|------|------|
| `debug.log` | 仅 Debug：窗口/画像/压缩/发送成功等高频细节 |
| `info.log` | 仅 Info：消息账本（入口+结局）、模型调用、写操作审计、启动里程碑 |
| `warn.log` | 仅 Warn：被拦截、护栏拒绝、各环节失败、429/401 |
| `error.log` | 仅 Error：服务级故障（带 stacktrace） |
| `fatal.log` | 仅 Fatal：启动致命错误 |
| `gin.log` | gin 每请求访问日志 |

滚动：单文件 10MB / 保留 5 备份 / 30 天。目录 `~/.plumebot/logs/`。

### 8.2 消息账本

每条消息**恰好一入口一结局**：入口行 → `Info("收到消息", …)`；结局行 → `Info|Warn("消息结局", …, outcome)`。`outcome` 常见值：`agent_replied`（触发并发送成功）/ `not_triggered` / `rate_limited` / `sensitive` / `command` / 各环节失败等。grep `消息结局` 即可对账某条消息的最终去向。

### 8.3 trace_id

关键路径日志统一带 trace_id，管理端 = 客户端 IP、QQ 侧 = `group:<群号>` / `private:<QQ号>`。一次会话的入口行 → 结局行 → 模型调用可按 trace_id 一键串联，管理控制台日志页按 trace_id 检索。

## 9. 架构概览

```
cmd ──→ handler ──→ service ──→ domain（接口）
                      │
                      └──→ infra（编译时注入）

infra ──→ domain（实现接口）
domain 零依赖
```

- **分层**：domain（纯接口 + 实体，零外部依赖）→ service（编排，依赖接口）→ infra（实现，封装第三方）；
- **单二进制**：纯 Go 无 cgo（`modernc.org/sqlite`），桌面机 / 服务器一样跑；
- **版本化迁移**：`schema_migrations` 逐版本单事务执行，失败整体回滚下次重试；
- **锁粒度**：per-session 分锁，不同群/私聊互不阻塞，持锁不含 LLM/IO。

详细设计见 [architecture.md](../architecture.md)。
